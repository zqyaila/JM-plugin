# JMReader（TRSS-Yunzai 插件 + Web PDF 下载器）

把 [JM Reader](https://github.com/Aether-1013/jm-reader)（一个 Kotlin + Jetpack Compose 的漫画阅读器）的核心能力移植到 **TRSS-Yunzai** QQ 机器人上，用 Node.js 复刻了它的完整网络协议（主机发现、请求签名、AES 响应解密、图片打乱还原）。

本仓库现在有**两种用法**，共用同一套核心模块：

| 形态 | 入口 | 适用场景 |
| --- | --- | --- |
| QQ 机器人插件 | `index.js` | 在群里发 `#jm1480269` 直接发回加密 PDF |
| 网页版 | `web/server.js` | 浏览器里搜索、选章节、看进度、下载 PDF，无需机器人环境 |

两者都支持 **HTTP / HTTPS / SOCKS5 代理下载**（可只代理接口、或只代理图片，或多代理轮换）。

在 Yunzai 根目录执行，用 `git clone` 拉取插件：

```bash
cd Yunzai
git clone https://github.com/zqyaila/JM-plugin ./plugins/JM-plugin/
```


然后进入插件目录安装依赖（图片打乱还原 + PDF 生成）：

```bash
cd plugins/JM-plugin
npm install
```

重启机器人

## Web 版（浏览器里下载 PDF）

不需要机器人环境，装好依赖后直接起服务即可（Node.js ≥ 18）：

```bash
cd plugins/JM-plugin      # 或者单独把整个目录拷到任意位置
npm install
npm run web               # 默认 http://127.0.0.1:7788
```

常用启动参数：

```bash
node web/server.js --port 8080            # 换端口
node web/server.js --host 0.0.0.0         # 允许局域网访问（手机/平板可用）
node web/server.js --token 我的口令        # 开启访问口令，公网暴露时必须加
node web/server.js --trust-proxy          # 放在 Nginx/Caddy 后面时加，按真实 IP 限流
```

也可以用环境变量：`JM_PORT`、`JM_HOST`、`JM_TOKEN`、`JM_TRUST_PROXY=1`。

### 网页版能做什么

- **搜索**：作品名 / 作者 / 标签，或直接粘贴 JM 号（纯数字、`JM123456`、链接都能识别）
- **详情抽屉**：封面、作者、标签、简介、章节列表、页数
- **收藏**：卡片右上角的心形、详情页的「收藏」一点即存；顶栏心形进入「我的收藏」，多设备（手机 / 电脑）共用同一份列表
- **选择范围**：整本，或自定义「第几章到第几章」
- **两种产出**：
  - **每章一个 PDF，打包 ZIP**（默认，多章作品）：zip 内是 `作品名_JM123456/001_第1章.pdf`、`002_第2章.pdf`…，同一作品一个文件夹，按章节顺序编号，解压即按顺序排好
  - **合并成一个 PDF**：单文件，上限 350 页（再多会撑爆 WASM 内存，服务端会直接拦下并提示改用分章）
- **PDF 加密**：不加密 / 用 JM 号作密码 / 自定义密码
- **实时进度**：SSE 推送，能看到「正在下载第 37/120 页」，可同时排队多个任务
- **缓存复用**：同一作品第二次下载直接命中本地缓存，秒出
- **读完即已下载**：整本在阅读器里看完后，可以直接用本地页面排版出 PDF，不联网、不消耗流量（细节见下文「整本看完 = 已经下载好了」）
- **断点续传**：PDF 下载支持 `Range`，传到一半断了可以接着下，不必重新生成
- **后台任务**：关掉网页不影响生成，回来看任务列表照样能下载
- **任务按作品归类**：任务面板里一行一部作品（`JM号 · 文件数 · 体积`），点开才看到具体章节；进行中的作品自动展开并显示进度，同一个作品的历史缓存也归在同一个文件夹里
- **代理设置**：界面上直接填代理、点一下测试连通性，支持多个代理轮换

生成的 PDF 存放在 `data/pdfs/`，与 QQ 插件共用同一份缓存；ZIP 包放在 `data/exports/`（保留最近 20 个、7 天，自动清理）。

分章模式下每章单独建文档、写完立刻落盘，所以再大的作品也不会把内存堆满 —— 这也是 `Aborted()` 的根治办法。单章超过 350 页会自动再切成 `_part1`、`_part2`。

### 在线阅读

不想先等几分钟生成 PDF 的话，可以直接在网页里看：

- **入口**：作品详情抽屉底部的「在线阅读」（有阅读记录时显示「继续阅读」）；任务面板里单章 PDF 的「在线阅读」按钮；地址 `#/read/<JM号>/<章节号>` 可以直接分享 / 收藏
- **阅读方式**：竖排连续滚动，条漫和页漫都适用；页面按真实比例占位，图片加载完版面不会跳动
- **按需加载**：只加载视口上下各 1400px 内的页面，30 页的章节也只先拉三四张，不会一次把整章图片全拉下来
- **章节切换**：顶栏下拉直接跳章，底栏「上一章 / 下一章」，键盘 `←` `→` 也行；读到结尾有「继续阅读下一章」
- **快捷操作**：`↑` `↓` / `PageUp` `PageDown` / `空格` 翻页，`Home` `End` 到首尾，`W` 切换排版宽度（适宽 / 宽屏 / 全宽），`F` 全屏，`Esc` 退出
- **阅读进度**：按作品记在浏览器本地，下次点「继续阅读」直接回到上次那一章那一页
- **图片处理**：服务端抓图 → 还原打乱页 → 还原结果是 PNG，会转成 JPEG 再发，省流量也省手机内存
- **边看边存**：读到第 N 页时后台顺手把 N+1~N+3 页也抓下来，往下滑基本不用等；看过的页除了内存缓存，还会**落盘到 `data/pages/`**，重启服务、隔几天再回来看同一章，直接读本地文件

阅读走的是独立的 `/api/read`（章节页表）和 `/api/page`（单页图片）接口：前端只传「章节 id + 页码」，图片地址由服务端从接口取，所以这个接口不会被当成任意 URL 的代理。

图片缓存分两层：内存里留最近 2 小时看过的（192 MB 上限，进程内 LRU），磁盘上留更久的 —— `data/pages/<章节 id>/<页码>.jpg`，旁边一个 `index.json` 记着每页的宽高，重启后首屏仍能按真实比例占位、不跳动。磁盘总量在设置里可调（「阅读缓存上限」，默认 512 MB，`0` = 不限），超了按章节淘汰最久没看的整章，不做单页删除。设置面板里也能看到当前占用、一键「清空阅读缓存」。

> 只有**看过**的页才会存，不会因为打开一章就整章下载；缓存和 `data/pdfs` 互不影响，清空阅读缓存也不会删已生成的 PDF。

### 整本看完 = 已经下载好了

阅读缓存不只是「省点流量」：每打开一章，服务端会把「这一章属于哪本、一共几页」登记到 `data/offline.json`。等一部作品的每一章都翻完，这本就等于已经下载到本机了 —— 剩下的只是「排版成 PDF」这一步。

- **阅读器里**：顶栏会显示 `本地 3/12 章`，整本看完变成绿色的 `整本已缓存`，最后一章末尾直接出现「整本已缓存 · 导出 PDF」按钮
- **详情抽屉**：新增「阅读缓存」区块，进度条 + `已看完几章 / 共几章 / 已缓存多少页 / 占多少空间`；整本缓存齐了按钮变成「导出 PDF（本地）」，没看完时是「用缓存导出（补下剩余页）」
- **任务面板**：顶部单独列出「整本已缓存」的作品，点一下就能出 PDF，和已下载的文件排在一起
- **快**：离线导出不请求作品详情、不请求章节页表、不下载任何图片，只从 `data/pages` 读图排版 —— 8 页的短篇不到 0.1 秒，几百页也就几十秒，**流量为 0**
- **断网也能用**：这条路径不碰 JM 接口，网络挂了照样能导出
- **没看完也能受益**：普通「开始生成」现在也会先看本地，看过的页直接复用，只补下没看过的页（任务完成时会写明「其中 N 页来自阅读缓存」）

几个约定：

- 整本缓存齐了的章节会被「软钉住」，LRU 淘汰时排在最后 —— 不然读一本 300 页的漫画，读到最后一章时第一章早被删了，「整本」永远凑不齐。软钉住只是排序优先，空间实在不够时仍然会被淘汰
- 合并成一个 PDF 仍是 350 页上限；超过就选「每章一个 PDF 打包」，两条路都只读本地缓存
- 清空阅读缓存会连登记簿一起清掉；手动删 `data/pages` 里的文件也不用担心，覆盖率是按磁盘实际文件算的，缺页会自己回落
- 离线导出用的就是阅读时那张 JPEG（阅读器会把它压到质量 88），不是图源原图；要最高画质仍然走联网导出

### 网页看过的，群里直接用

网页端和插件本体跑在两个进程里，但**共用同一份缓存目录**：

| 目录 | 谁写 | 谁读 |
|---|---|---|
| `data/pdfs/` + `data/index.json` | 网页任务、插件 | 两边都读，命中就直接发文件 |
| `data/pages/`（在线阅读的页） | 只有网页进程 | 插件**只读**复用 |

也就是说：在网页里看完 200 页，回头在群里 `#jm<号>`，这 200 页会直接从硬盘读，只有没看过的页才联网下载。任务完成时会写明「其中 N 页取自网页阅读缓存，没有重复下载」。

v1.6.6 起，**整段都看全**时走的是另一条路：不再请求作品详情、不再请求章节页表，直接从 `data/offline.json` 拿章节结构、从 `data/pages` 读图排版，**完全不联网**。

| 场景 | 机器人提示 | 实际行为 |
|---|---|---|
| 这一段全看完了 | `⚡ 本地缓存已齐全，正在合成加密 PDF…` + `N 页全部来自网页阅读缓存，不联网` | 0 次网络请求，35 页约 0.1–1 秒 |
| 只看了一部分 | `⚡ 正在用本地缓存生成加密 PDF…` + `共 35 页，本地已有 30 页，剩余 5 页联网下载（约 2 秒）` | 只补下缺的页；预计时间按**剩余页数**算，不再按总页数 |
| 没看过 | `⏳ 正在下载并生成加密 PDF…` + `预计 35 页，约 13 秒` | 和以前一样 |

- **开关**：锅巴面板「复用网页阅读缓存」，默认开。关掉就回到每页都重新下载
- **插件不写不删**：`data/pages` 的写入和 LRU 淘汰只归网页进程，插件以只读方式打开，不会与网页互相覆盖，也不会把你正在看的章节删掉
- **新页也能看到**：插件每次任务开始前会重新读一次磁盘，网页刚看完的章节不用重启插件
- **密码对不上会重下**：插件用 `pdfPassword`、网页用 `web-config.json` 里的加密设置，是两套配置。如果缓存那份 PDF 是用另一套密码（或干脆没密码）生成的，插件会按自己的配置重新生成一次 —— 否则发出去的文件，用户按提示输入的密码打不开
- **画质**：复用的是阅读时那张 JPEG（质量 88），不是图源原图；要最高画质把「复用网页阅读缓存」关掉

### 收藏

网页版有一套自己的收藏夹，**不需要登录 JM 账号**（网站的 `/favorite` 接口要会员态，而 Web 端本来就只有访问口令，没有账号体系）。

- **怎么收藏**：搜索结果 / 收藏列表的卡片，鼠标移上去右上角出现心形，点一下就是收藏；触屏没有 hover，心形常显。作品详情里标签行的「收藏 / 已收藏」是同一个开关。点收藏不会误触打开详情。
- **在哪看**：顶栏的心形图标，角标是数量；点开把主区域切成「我的收藏」，按收藏时间倒序。卡片上会顺带显示「读到第 N 章」（如果这本书有阅读记录）。
- **取消**：再点一次心形。收藏页里取消只拿掉那一张卡片，不整页重排，滚动位置不会跳。
- **存在哪**：服务端 `data/favorites.json`，只记 JM 号 / 名称 / 作者 / 收藏时间；封面仍走 `/api/cover` 的缓存，不额外占空间。手机和电脑打开同一个服务，看到的是同一份收藏。
- **上限**：5000 部；列表一次最多渲染最近 200 部（再多就只显示最近 200，数据不会丢）。
- **写盘**：临时文件 + rename，进程被杀不会留下半个 JSON；文件坏了会自动另存 `favorites.json.broken-<时间戳>` 并按空收藏夹启动，不会因此起不来。

> 命令层的 `#jm收藏` 走的是会员账号的云端收藏，需要 `#jm登录`；和网页这份本地收藏互不影响。

### 对外开放（公网 / 组网）

默认只监听 `127.0.0.1`，只有本机能访问。要让别人用，三选一。

**1. 直接暴露端口 + 访问口令**（最快，适合临时用）

```bash
node web/server.js --host 0.0.0.0 --port 7788 --token 你的口令
```

访问 `http://服务器IP:7788`，页面会先要求输入口令；口令只存在访问者自己的浏览器里，之后不再打扰。

**口令可以设多个**，给家人朋友各发一个，谁泄露了删掉那一条就行：

```bash
node web/server.js --host 0.0.0.0 --token 甲口令,乙口令,丙口令
```

也可以启动后再加：网页「设置 → 访问口令（每行一个）」，保存即生效，**不用重启**。命令行 `--token` 的那些始终有效，不会出现在这个列表里；删掉列表里的某一条，用它的设备下次请求就会被拦回口令页。

**口令页是全屏的**：没输对之前，页面里只有一个输入框 —— 搜索框、封面墙、18+ 提示都不会渲染，也读不到任何接口数据。口令正确后才继续。

也可以把口令拼进链接直接发给别人：`http://服务器IP:7788/?token=你的口令` —— 页面读到后会立刻把它从地址栏抹掉，不留在浏览历史和截图里。

⚠️ 这种方式是明文 HTTP，口令和下载的 PDF 都可能被链路中间人看到。长期使用走下面两种。

**2. 反向代理 + HTTPS**（推荐）

Caddy，证书自动签：

```
jm.example.com {
    reverse_proxy 127.0.0.1:7788
}
```

Nginx：

```nginx
location / {
    proxy_pass http://127.0.0.1:7788;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_buffering off;        # SSE 进度需要，否则进度会攒到最后一起吐
    proxy_read_timeout 3600s;   # 大作品生成耗时长
}
```

反代后启动时加 `--trust-proxy`，让限流按真实访客 IP 计数，而不是所有请求都算在 `127.0.0.1` 头上：

```bash
node web/server.js --token 你的口令 --trust-proxy
```

不加 `--trust-proxy` 时**不会**采信 `X-Forwarded-For`，否则任何人都能伪造 IP 绕过口令限流。

**3. 组网**（不暴露公网，最安全）

装 Tailscale / ZeroTier，把要用的设备拉进同一虚拟局域网，服务照常 `--host 0.0.0.0` 启动，通过虚拟网 IP 访问，例如 `http://100.x.x.x:7788`。公网扫不到端口，也不用改安全组。

**口令防护**：同一 IP 连续输错 10 次锁定 10 分钟（返回 429）；口令比较用哈希后的恒定时间比较，不泄漏长度和时序。多个口令时逐个比对、任一对上即放行，不会因为列表变长而变慢（哈希在内存里缓存，配置变了才重算）。中文口令也支持（浏览器只在 query 里送，不走 header）。为了不误伤自己人，计数有三条规矩：

- **只统计「带了口令但不对」的请求**。封面、页图这类 `<img>` 请求漏拼一次 token，会在几百毫秒里刷出几十条 401 —— 早期版本正是被自己的封面图锁死的，现在完全没带口令只返回 401，不计数。
- **同一 IP 一秒内的并发失败只算一次**，浏览器缓存了旧口令、一开页面并发几十个请求，不会被瞬间判成爆破。
- **口令正确就立刻放行并清零**。万一已经被锁，输对一次就马上恢复，不用干等十分钟（重启服务同样会清空）。

**防火墙**：直接暴露时记得放行端口，如 `ufw allow 7788/tcp`；云服务器还要在控制台的安全组里放行，只开 7788 这一项即可。

#### 手机 / 别的电脑打不开？按这三步查

```bash
# 1. 看监听地址：127.0.0.1 就只能本机访问，0.0.0.0 才是对外开放
ss -lntp | grep 7788

# 2. 看端口有没有被旧进程占着（旧进程往往只监听 127.0.0.1，你以为重启了其实没生效）
lsof -i :7788

# 3. 在服务器本机上验证服务是否活着
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:7788/api/health
```

- 第 1 步显示 `127.0.0.1:7788` → 用 `npm run web:lan` 或 `--host 0.0.0.0 --token 口令` 重启；v1.3.1 起启动日志会直接列出「其它设备可用的地址」。
- 第 1 步正常、第 2 步有旧进程 → 先 `kill` 掉再启动，否则新进程会以「端口被占用」退出。
- 都正常但还是连不上 → 查防火墙/安全组，以及两台设备是否真的在同一网段（Tailscale 先 `tailscale status` 看是否 online）。
- 反向代理场景下出现 `401`/`429` 且停不下来 → 是口令连错 10 次被锁 10 分钟，等一会儿或重启服务即可。

### 部署提示

- 反向代理务必关闭 SSE 缓冲（本服务已发送 `X-Accel-Buffering: no`，Nginx 仍需 `proxy_buffering off;`）。
- 整本下载会占用较多内存与带宽，`data/` 目录会持续增长，记得定期清理。
- 服务没有内置多用户体系：拿到口令的人权限相同，都能生成任务、读缓存列表。只分享给可信的人。

## 网络代理

核心协议与图片下载原本直连，现在可以整体或部分走代理，用来解决「接口能连、图片 CDN 连不上」或反过来「图片能直连、接口被墙」的情况。

**支持的格式**（零第三方依赖，手写 CONNECT 隧道与 SOCKS5 握手）：

```
http://127.0.0.1:7890
https://user:pass@127.0.0.1:8443
socks5://127.0.0.1:1080
socks5://user:pass@127.0.0.1:1080
127.0.0.1:7890                 # 省略协议时按 http 处理
```

**多个代理**用逗号或换行分隔，请求失败时会自动轮换到下一个：

```
http://127.0.0.1:7890, socks5://127.0.0.1:1080
```

**生效范围**（`proxyMode`）：

| 值 | 含义 |
| --- | --- |
| `all` | 接口与图片都走代理 |
| `api` | 只有接口请求走代理，图片直连 |
| `image` | 只有图片下载走代理，接口直连 |
| `off` | 关闭代理 |

三种配置方式：

1. **锅巴面板** — 「网络代理」分组里填地址、选范围
2. **命令** — `#jm代理 <地址>`、`#jm代理 范围 api`、`#jm代理 测试`、`#jm代理 关闭`
3. **网页版** — 右上角设置里填地址，点「测试代理连通性」看出口 IP 与延迟

> 代理密码会以明文保存在配置文件中（`config/jmreader.yaml` 或 `data/web-config.json`），界面上只显示 `***`。用命令设置时代理串会留在聊天记录里，介意的话请改用配置文件或网页版。

- 🔥 **热门 / 随机 / 分类** — `#jm热门` `#jm随机` `#jm分类`
- 👤 **会员** — `#jm登录` / `#jm退出` / `#jm收藏` / `#jm历史`
- 🗑 **资源管理（主人）** — `#jm删除` / `#jm清缓存` / `#jm缓存` 管理缓存 PDF
- 📚 **多章节下载** — `#jm<号> 1-5` 合并成一个 PDF，`1-x` 到最后一章，`--split` 分章逐个发；合并页数上限可配
- 🖥 **锅巴网页配置** — 通过锅巴面板可视化配置通用密码、每页条数等
- 🌐 **代理下载** — 支持 HTTP / HTTPS / SOCKS5，可只代理接口或只代理图片，多代理自动轮换

### PDF 加密说明（双密码）

`#jm<数字>` 生成的 PDF 带**两个打开密码**，二选一即可打开：

```
密码 1（通用密码）= 插件配置里的 pdfPassword
密码 2（作品ID）  = 漫画的 JM 号
```

- **通用密码**：在锅巴面板或 `#jm密码 <新密码>` 设置，默认空。留空则 PDF 仅能用「作品ID」打开。
- **作品ID**：每个漫画唯一的 JM 号（如 `1480269`），天然不同，无需配置。
- 加密采用 PDF 标准安全处理器（RC4/AES-128，PDF 1.7），主流阅读器（Adobe、浏览器、WPS）都能正常打开并输入密码。

### 合并 PDF 的页数上限

多个章节合成一个 PDF 时，页数越多，WASM 生成时的内存峰值越高。上限默认 **350 页**，可以自己往上试：

- **插件**：锅巴面板「合并 PDF 页数上限」，或 `config/jmreader.yaml` 里的 `mergePageLimit`（1–5000）
- **网页**：设置面板「合并 PDF 页数上限」，保存后立即生效（影响新任务，不影响已开始的）

超过上限时不会硬扛：合并任务直接报错并提示改用 `--split`（插件）或「每章一个 PDF 打包」（网页）。两者都是分卷，不会因为一个上限把整本卡死。

> 和「整本页数上限」（`maxPages`）不是一回事：`maxPages` 是**拒绝下载**的总量阈值（0 = 不限），`mergePageLimit` 是**单个 PDF 文件**的容量阈值。前者防"下太多"，后者防"合太大"。

### 持久化缓存

下载过的 PDF 会缓存到插件目录 `data/pdfs/`，之后**在任何群/私聊**再次请求同一作品（同章节）会直接命中缓存、秒发，无需重新下载。

- 缓存索引在 `data/index.json`，写入用「临时文件 + rename」，进程被杀不会留下半个 JSON；索引损坏时会先备份成 `index.json.broken-<时间戳>` 再按目录重建，不会静默清空。
- 网页服务和插件是两个进程，都可能写索引，所以写入全程持有一把文件锁（`index.json.lock`），并发下载不会互相覆盖条目。
- 只重建出来的条目（`recovered`）因为不知道原密码，会被当作「密码策略不明」，下次请求时按当前配置重新生成一次。
- 主人可用 `#jm缓存` 查看、`#jm删除 <JM号> [章节]` 删单个、`#jm清缓存` 清空全部。

## 实现原理

与 Kotlin 版 `app/src/main/kotlin/com/jm/reader/data/net/` 一一对应：

1. **主机发现** — 从 CDN 拉取加密服务器列表（AES 解密，key = `md5("diosfjckwpqpdfjkvnqQjsik")`），
   逐个用 `GET /setting` 探测，取第一个 `code:200` 的主机，失败回退内置主机。
2. **请求签名** — 每个请求带 `Tokenparam` = `<unixSecs>,<appVersion>`、
   `Token` = `md5("<unixSecs>185Hcomic3PAPP7R")`。
3. **响应加密** — `{ "code":200, "data":"<base64 AES-256-ECB>" }`，
   解密 key = `md5("<本次时间戳>185Hcomic3PAPP7R")`（必须用本次请求发送的时间戳）。
4. **图片打乱** — 阅读器按 `md5(专辑ID + 页码)` 计算切片数，重组倒序水平条带。

## 配置

本插件配置保存在 Yunzai 的 `config/jmreader.yaml`（首次运行自动生成）：

```yaml
pdfPassword: ''        # PDF 通用密码（userPassword），与作品ID（ownerPassword）构成双密码
pageSize: 10           # 列表每页显示条数（1-20）
imageQuality: 82       # PDF 内页 JPEG 压缩质量（1-100）
maxPages: 0            # PDF 最大页数限制（0 = 不限制），超过则拒绝并提示
downloadConcurrency: 4 # 下载图片并发数（1-10）
mergePageLimit: 350    # 多章合并成一个 PDF 的页数上限（1-5000）
usePageCache: true     # 复用网页端「在线阅读」留下的页缓存
proxy: ''              # 代理地址，如 http://127.0.0.1:7890；多个用逗号分隔；留空=直连
proxyMode: all         # 代理生效范围：all / api / image / off
```

可通过两种方式修改：

- **锅巴面板**（推荐）：装好 [guoba-plugin-next](https://github.com/cchanlan/guoba-plugin-next) 后，本插件配置会自动出现在锅巴面板里，可视化修改通用密码、每页条数、最大页数等。
- **命令**：`#jm密码 <新密码>` 设置通用密码、`#jm密码 清空` 清空。

其余无需额外配置即可使用（主机自动发现）。如需调整：

- **接口语言**：默认 `TW`（繁体），在 `apps/jmcore.js` 里 `this.lang` 改为 `CN` 即简体。
- **图片主机**：默认自动从 `/setting` 获取，兜底 `cdn-msp3.jmdanjonproxy.vip`。

### 锅巴网页配置接入说明

`guoba.support.js` 暴露了 `supportGuoba()`，向锅巴面板提供以下配置项：

| 配置项 | 类型 | 说明 |
| --- | --- | --- |
| `pdfPassword` | Input | PDF 通用密码 |
| `pageSize` | InputNumber | 每页显示条数（1-20） |
| `imageQuality` | InputNumber | 图片压缩质量（0-100） |
| `maxPages` | InputNumber | PDF 最大页数限制（0 = 不限制） |
| `downloadConcurrency` | InputNumber | 下载图片并发数（1-10） |
| `mergePageLimit` | InputNumber | 多章合并成一个 PDF 的页数上限（1-5000，默认 350） |
| `usePageCache` | Switch | 复用网页端阅读缓存 |
| `proxy` | InputTextArea | 代理地址，可填多个（逗号/换行分隔） |
| `proxyMode` | Select | 代理生效范围 all / api / image / off |

锅巴面板保存时优先走 `index.js` 注册的全局钩子（改内存 + 写 `config/jmreader.yaml`，即时生效）；插件没加载时直接改这份 yaml 兜底，所以不会出现「点了保存没反应」。

> **面板里找不到「合并 PDF 页数上限」或改了不生效？**
>
> 1. 这一项是 v1.6.4 加的。锅巴在启动时缓存 `guoba.support.js`，更新插件后必须**重启一次云崽**（或在面板里重载插件），新字段才会出现。
> 2. 保存后看提示：显示「已保存（插件未运行，重启后生效）」说明走的是文件兜底通道，重启即可；显示「保存成功~」说明已即时生效。
> 3. 想确认写到哪了，直接看 `config/jmreader.yaml` 里的 `mergePageLimit`。
> 4. 网页版的合并上限是另一份配置（`data/web-config.json`，在网页右上角设置里改），与插件这份互不影响。

## 网页「加载慢 / 打不开」排查

页面本身是三张小文件（`index.html` + `style.css` + `app.js`，gzip 后约 40 KB），局域网内正常都在 1 秒内出首屏。如果卡住，按这个顺序看：

1. **看服务端控制台**：v1.3.0 起，任何超过 1.2 秒的请求都会打一条日志，例如
   `[slow] GET /api/search?q=... 4210ms` —— 直接告诉你时间花在哪个接口上。
2. **看顶部三个数字**：
   - `…` = 正在拉取；
   - `未连接`（黄色）= 6~8 秒内后端没回话，**点一下这块数字即可重连**；
   - 一直停在 `–` = `app.js` 没跑起来，多半被浏览器缓存或弹窗拦截了，`Ctrl+F5` /「清除站点数据」重开。
3. **首次搜索慢是正常的**：要先拉镜像站配置、探测可用主机，通常 3~10 秒；成功后会写入 `data/api-host.json`，之后启动直接复用，一般 1 秒内。搜索期间超过 4 秒会弹提示告诉你「正在连接镜像站」。
   - v1.5.2 起，接口请求不再「一次卡 20 秒、串行重试三次」：单次 10 秒封顶，且第一次 2.5 秒没回来就并行补发一次（自动换下一个代理），谁先成功用谁。所以代理里有一个节点坏掉时，搜索是 3~4 秒出来，而不是等 20 秒后重试。全部节点都不可用时约 15 秒报错，不再是一分钟白屏。
   - 服务器已明确返回错误（作品下架、口令不对）时只请求一次，不会重试三次。
4. **封面是现抓的**：一屏 24 张图，服务端限制 4 张并发 + 内存缓存 1 小时；图片慢不影响列表和按钮，不要以为页面卡死。
5. **同一台机器正在生成 PDF 会抢 CPU**：低配设备（NAS / 软路由 / 1 核小主机）建议把「图片质量」调到 70、「下载并发」调到 2，页面会明显跟手。
6. **组网 / 公网访问**：先确认带宽和丢包（`ping` / `iperf`）；反向代理要关掉对 SSE 的缓冲（`proxy_buffering off;`），否则任务进度条会一直不动。
7. **升级后仍显示旧界面**：静态资源带 `?v=` 的会被浏览器长期强缓存，正常升级会自动换 URL；如果手工改过文件，`Ctrl+F5` 一次即可。

## 已知限制

- `sharp` / `@muhammara/wasm` 未安装时无法生成 PDF。
- 评论/签到/收藏管理等进阶接口已在 `apps/jm.js` 预留，命令层未全部接出，可按需扩展。
- 登录密码会出现在聊天记录里，请仅在私聊/可信环境使用。
- 整本漫画合成 PDF 会较大，发送大文件时可能受 QQ 群文件大小限制；建议单章下载，或分卷。
- 单个合并 PDF 上限 350 页：`@muhammara/wasm` 的线性内存有限，一个文档塞上千页会直接 `Aborted()`。网页端可在详情页改用「每章一个 PDF 打包」；QQ 命令端遇到超限会提示改单章下载。
- 超长连载（比如上百章、几万页）整本打包要跑很久、ZIP 可能上 GB：建议按「第 1–30 章」「第 31–60 章」分批下，边下边存的单章缓存下次会自动复用，不会重下。
- 分章打包时单章失败不会再让整个任务失败：失败章节会跳过并记在任务卡片上，重跑同一范围时已完成的章节直接命中缓存，只需补下失败的那几章。
- 缓存不设过期时间（除非主人手动删除），长期使用会占用磁盘；可用 `#jm清缓存` 清理。
- 代理只作用于本插件/本服务的请求，不改系统代理、不影响机器上其它程序。
- 网页版任务队列保存在内存中：关掉浏览器不影响生成，但**重启服务**会让「进行中」的任务丢失（已生成的 PDF 与缓存仍在 `data/pdfs/`）。
- 网页版默认单机使用；对公网开放请自行加反向代理与访问口令，并注意 `data/` 目录的访问权限。
